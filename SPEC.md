## 1. Назначение

BuggatiBistroLettati — трансформируемое средство передвижения, способное перемещаться по земле и в воздухе.

В `road` аппарат движется на колёсах. В `hover` четыре колеса трансформируются в подъёмные роторы. В `flight` двери раскрываются и выполняют функцию крыльев, а поступательное движение создаёт постоянно работающая турбина.

Единственный энергетический ресурс модели — топливо. Турбина считается постоянно работающей, поэтому отдельного публичного состояния `turbines_active` нет.

## 2. Стихия и конструкционные элементы

Стихия: воздух.

Конструкционные элементы:

- четыре трансформируемых колеса-ротора;
- две двери-крыла;
- постоянно работающая турбина.

У транспорта три режима:

- `road` — наземное движение;
- `hover` — вертикальный полёт/зависание на роторах;
- `flight` — поступательный полёт на крыльях.

Из любого режима разрешён **прямой переход в любой другой режим**, если соблюдены физические условия перехода.

```text
          ROAD
         ↙    ↘
        ↕      ↕
     HOVER ↔ FLIGHT
```

В частности, `road -> flight` является прямым переходом: транспорт раскрывает крылья, разгоняется по земле как обычный самолёт и взлетает. Переход через `hover` для этого не требуется.

## 3. Публичный интерфейс

### 3.1. Класс и конструктор

```python
class LegoVehicle:
    MAX_PAYLOAD_KG: float
    FUEL_TANK_CAPACITY_L: float
    MIN_FUEL_L: float

    _speed: float

    def __init__(
        self,
        payload_kg: float,
        fuel_l: float,
    ) -> None:
        ...
```

| Параметр | Тип | Единица | Диапазон |
|---|---|---|---|
| `payload_kg` | `float` | кг | `0 ... MAX_PAYLOAD_KG` |
| `fuel_l` | `float` | л | `0 ... FUEL_TANK_CAPACITY_L` |


`MIN_FUEL_L` — неприкосновенный аварийный запас топлива. При обычном движении в воздухе он не расходуется. Он предназначен для автоматического аварийного возвращения в `ROAD-mode`.

Начальное состояние:

```text
current_mode == "road"
target_mode == "road"

rotors_deployed == False
wings_deployed == False

is_ground == True
is_airborne == False

_speed == 0
```

### 3.2. Публичные атрибуты

| Атрибут | Тип | Описание |
|---|---|---|
| `payload_kg` | `float` | Полезная нагрузка |
| `fuel_l` | `float` | Текущий запас топлива |
| `current_mode` | `str` | Последний полностью достигнутый режим |
| `target_mode` | `str` | Режим, в который транспорт сейчас переходит |
| `rotors_deployed` | `bool` | Колёса находятся в положении роторов |
| `wings_deployed` | `bool` | Двери находятся в положении крыльев |
| `is_airborne` | `bool` | Транспорт находится в воздухе |
| `is_ground` | `bool` | Транспорт находится на земле |

Всегда:

```text
is_ground == not is_airborne
```

### 3.3. current_mode и target_mode

`current_mode` описывает последний завершённый устойчивый режим.

`target_mode` описывает цель текущего перехода.

Если:

```text
current_mode == target_mode
```

переход не выполняется.

Если:

```text
current_mode != target_mode
```

транспорт находится в переходном процессе. В этот момент конструкционные элементы могут иметь промежуточную конфигурацию.

После успешного завершения:

```text
current_mode = target_mode
```

### 3.4. Устойчивые конфигурации

| `current_mode` | Роторы | Крылья | Положение |
|---|---|---|---|
| `road` | сложены / колёса | сложены | земля |
| `hover` | раскрыты | сложены | воздух |
| `flight` | сложены | раскрыты | воздух |

Промежуточная комбинация конструкционных элементов разрешена только во время перехода.

### 3.5. Внутренняя скорость

```python
_speed: float
```

`_speed` — внутренний физический параметр поступательного движения относительно среды.

Он:
- не задаётся пользователем;
- не является публичным атрибутом;
- изменяется внутренней логикой `move()` и переходов;
- используется для проверки физических условий смены режима.

Точная формула `_speed` не входит в публичный контракт. Публично наблюдаемым является только результат: разрешён переход или нет.

## 4. State-machine

State-machine определяет не маршрут через другие режимы, а **условия прямого перехода** между двумя режимами.

### 4.1. ROAD -> HOVER

Цель — вертикальный взлёт.

Переходная конфигурация:

```text
current_mode == "road"
target_mode == "hover"

rotors_deployed: False -> True
wings_deployed == False
is_ground: True -> False
```

Факторы:

- транспорт находится на земле;
- топлива достаточно для взлёта и сохранения `MIN_FUEL_L`;
- роторы могут быть безопасно раскрыты.

После завершения:

```text
current_mode == "hover"
target_mode == "hover"
rotors_deployed == True
wings_deployed == False
is_airborne == True
```

### 4.2. ROAD -> FLIGHT

Цель — самолётный взлёт непосредственно с земли.

Переходная конфигурация:

```text
current_mode == "road"
target_mode == "flight"

rotors_deployed == False
wings_deployed: False -> True
```

Факторы:

- транспорт находится на земле;
- крылья раскрыты;
- транспорт разгоняется на колёсах;
- внутренней `_speed` достаточно для самолётного взлёта;
- топлива достаточно для выполнения перехода и сохранения `MIN_FUEL_L`.

После отрыва от земли:

```text
current_mode == "flight"
target_mode == "flight"
rotors_deployed == False
wings_deployed == True
is_airborne == True
is_ground == False
```

`hover` в этом переходе не используется.

### 4.3. HOVER -> ROAD

Цель — вертикально приземлиться и перейти на колёса.

Факторы:

- роторы раскрыты;
- транспорт снижает высоту;
- после касания земли роторы могут быть сложены в колёса.

После завершения:

```text
current_mode == "road"
target_mode == "road"
rotors_deployed == False
wings_deployed == False
is_ground == True
```

### 4.4. HOVER -> FLIGHT

Цель — перейти от вертикального полёта к поступательному.

Переходная конфигурация может содержать одновременно:

```text
rotors_deployed == True
wings_deployed == True
```

Факторы:

- сначала раскрываются крылья;
- транспорт набирает поступательное движение;
- после достижения допустимого внутреннего `_speed` роторы складываются.

После завершения:

```text
current_mode == "flight"
target_mode == "flight"
rotors_deployed == False
wings_deployed == True
is_airborne == True
```

### 4.5. FLIGHT -> HOVER

Цель — перейти от поступательного полёта к удержанию на роторах.

Переходная конфигурация:

```text
rotors_deployed == True
wings_deployed == True
```

Факторы:

- роторы раскрываются до потери необходимой крыльям поступательной скорости;
- `_speed` уменьшается;
- после перехода нагрузки на роторы крылья складываются.

После завершения:

```text
current_mode == "hover"
target_mode == "hover"
rotors_deployed == True
wings_deployed == False
is_airborne == True
```

### 4.6. FLIGHT -> ROAD

Цель — самолётная посадка непосредственно из `flight`.

Переход через `hover` не обязателен.

Факторы:

- крылья остаются раскрытыми во время снижения;
- сохраняется необходимое поступательное движение;
- транспорт касается земли на колёсах;
- после безопасного завершения пробега крылья складываются.

После завершения:

```text
current_mode == "road"
target_mode == "road"
rotors_deployed == False
wings_deployed == False
is_ground == True
is_airborne == False
```

## 5. Сводная таблица переходов

| Current | Target | Прямой переход | Основной фактор | Переходная конструкция |
|---|---|---|---|---|
| ROAD | HOVER | да | вертикальный взлёт | раскрываются роторы |
| ROAD | FLIGHT | да | разгон до взлёта | раскрываются крылья |
| HOVER | ROAD | да | вертикальная посадка | роторы до касания земли |
| HOVER | FLIGHT | да | набор поступательного движения | роторы + крылья |
| FLIGHT | HOVER | да | снижение поступательного движения | крылья + роторы |
| FLIGHT | ROAD | да | самолётная посадка | крылья до касания земли |

## 6. Топливо и аварийный резерв

Топливо — единственный энергетический ресурс.

`MIN_FUEL_L` резервируется исключительно для аварийного возвращения в `road`.

Обычная операция в `hover` или `flight` разрешена только тогда, когда после неё:

```text
fuel_l >= MIN_FUEL_L
```

Обычный переход **из `road` в воздушный режим** также разрешён только тогда, когда после перехода останется не менее `MIN_FUEL_L`.

Если во время `move()` или `hover()` выясняется, что запрошенную операцию нельзя полностью выполнить без расходования аварийного резерва, обычное действие не продолжается. Вместо этого автоматически инициируется аварийное возвращение в `road`.

### 6.1. Аварийное возвращение из HOVER

```text
current_mode = hover
target_mode = road
```

Используется прямой аварийный переход:

```text
HOVER -> ROAD
```

Роторы обеспечивают контролируемое снижение. После касания земли они складываются в колёса.

На этот переход разрешено расходовать `MIN_FUEL_L`.

### 6.2. Аварийное возвращение из FLIGHT

При недостатке топлива в `flight` система должна вернуть транспорт в `road`.

Предпочтительный прямой путь:

```text
FLIGHT -> ROAD
```

если текущие физические условия позволяют безопасную самолётную посадку.

Если прямой переход физически невозможен в текущем состоянии, допускается аварийная последовательность:

```text
FLIGHT -> HOVER -> ROAD
```

Для неё сначала скорость опускается до 0, затем раскрываются роторы и выполняется переход в `hover`, затем выполняется вертикальная посадка.

`MIN_FUEL_L` должен быть рассчитан при проектировании так, чтобы гарантированно покрывать более затратный из допустимых аварийных путей.

Во время уже начатого аварийного возвращения ограничение:

```text
fuel_l >= MIN_FUEL_L
```

больше не применяется: резерв разрешено расходовать вплоть до завершения перехода в `road`.

## 7. Публичные методы

### 7.1. move

```python
def move(
    self,
    direction: str,
    duration_min: float,
    power_usage: float,
) -> None:
    ...
```

Общая команда движения. Конкретные проверки конструкции, изменение `_speed`, расход топлива и физика движения делегируются внутреннему коду.

Допустимые направления:

| Режим | Направления |
|---|---|
| `road` | `forward`, `backward` |
| `hover` | `up`, `down`, `forward`, `backward`, `left`, `right` |
| `flight` | `forward`, `up`, `down`, `left`, `right` |

Перед выполнением метод рассчитывает, можно ли полностью выполнить действие с сохранением аварийного резерва.

Если топлива хватает:

1. выполняется движение;
2. уменьшается `fuel_l`;
3. внутренняя `_speed` изменяется в соответствии с движением.

Если транспорт находится в `hover` или `flight` и топлива на запрошенное движение без использования `MIN_FUEL_L` не хватает:

1. запрошенное обычное движение не выполняется полностью;
2. `target_mode` автоматически устанавливается в `"road"`;
3. запускается аварийный переход в `road`;
4. аварийному переходу разрешено использовать `MIN_FUEL_L`.

Таким образом, нехватка топлива в воздухе не оставляет объект в невозможном воздушном состоянии.

Если топлива недостаточно даже для аварийного возвращения, возникает `NotEnoughFuel`.

### 7.2. hover

```python
def hover(
    self,
    duration_min: float,
    power_usage: float,
) -> None:
    ...
```

Удерживает транспорт неподвижно в воздухе.

Разрешён только если:

```text
current_mode == "hover"
target_mode == "hover"
rotors_deployed == True
is_airborne == True
```

Перед выполнением проверяется возможность полного зависания с сохранением `MIN_FUEL_L`.

Если топлива хватает — выполняется обычное зависание.

Если топлива недостаточно без использования аварийного резерва:

```text
target_mode = "road"
```

и вместо продолжения зависания начинается аварийное снижение `HOVER -> ROAD`.

Если топлива недостаточно даже для аварийного приземления — `NotEnoughFuel`.

### 7.3. change_mode

```python
def change_mode(self, target_mode: str) -> None:
    ...
```

Задаёт требуемый режим.

Разрешены все шесть прямых переходов:

```text
road -> hover
road -> flight
hover -> road
hover -> flight
flight -> road
flight -> hover
```

Метод устанавливает `target_mode`. Физическое завершение перехода зависит от факторов state-machine: положения, `_speed`, состояния роторов, крыльев и доступного топлива.

Для перехода из `road` в `hover` или `flight` должно быть достаточно топлива, чтобы после перехода сохранить `MIN_FUEL_L`.

### 7.4. deploy_rotors

```python
def deploy_rotors(self) -> None:
    ...
```

Раскрывает роторы.

Допустимость определяется текущим переходом и физическим состоянием.

Типичные допустимые случаи:

- подготовка `road -> hover`;
- подготовка `flight -> hover`;
- аварийная подготовка `flight -> hover -> road`.

Само раскрытие роторов не обязано мгновенно изменять `current_mode`.

### 7.5. retract_rotors

```python
def retract_rotors(self) -> None:
    ...
```

Складывает роторы.

Роторы нельзя сложить, пока они являются единственным элементом, обеспечивающим нахождение транспорта в воздухе.

При `hover -> flight` они складываются только после достижения условий устойчивого полёта на крыльях.

При `hover -> road` они складываются после касания земли.

### 7.6. deploy_wings

```python
def deploy_wings(self) -> None:
    ...
```

Раскрывает крылья.

Используется:

- при `road -> flight` до разгона и взлёта;
- при `hover -> flight` до складывания роторов;
- в `flight`.

Само раскрытие крыльев не меняет `current_mode`.

### 7.7. retract_wings

```python
def retract_wings(self) -> None:
    ...
```

Складывает крылья.

При `flight -> hover` крылья складываются только после того, как роторы способны удерживать транспорт.

При `flight -> road` крылья складываются после безопасного приземления/завершения посадочного движения.
