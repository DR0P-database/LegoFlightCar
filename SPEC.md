## 1. Назначение

`LegoVehicle` — модель трансформируемого транспорта с тремя устойчивыми режимами:

- `road` — движение по земле на колёсах;
- `hover` — вертикальный полёт или зависание на роторах;
- `flight` — поступательный полёт на крыльях.

Модель дискретная: каждый публичный метод атомарно выполняет своё действие. `change_mode()` только записывает цель, а остальные методы либо полностью завершают операцию, либо при исключении не меняют состояние. Координаты, высота и реальная аэродинамика не моделируются.

## 2. Публичная модель

### 2.1. Класс и константы

```python
class LegoVehicle:
    MAX_PAYLOAD_KG = 200.0
    FUEL_TANK_CAPACITY_L = 60.0
    MIN_FUEL_L = 4.0
    TRANSITION_FUEL_L = 2.0
    MIN_FLIGHT_SPEED_KMH = 80.0

    ROAD_FUEL_RATE_L_PER_MIN = 0.10
    HOVER_FUEL_RATE_L_PER_MIN = 0.40
    FLIGHT_FUEL_RATE_L_PER_MIN = 0.30

    def __init__(self, payload_kg: float, fuel_l: float) -> None:
        ...

    def change_mode(self, target_mode: str) -> None:
        ...

    def transition(self) -> None:
        ...

    def move(
        self,
        direction: str,
        duration_min: float,
        power_usage: float,
    ) -> None:
        ...

    def hover(self, duration_min: float, power_usage: float) -> None:
        ...

    def get_status(self) -> dict:
        ...
```

Раскрытие и складывание роторов и крыльев не являются отдельными публичными командами. Ими управляет только `transition()`, поэтому пользователь не может оставить объект в промежуточной конфигурации.

Допустимые значения:

```text
0 <= payload_kg <= MAX_PAYLOAD_KG
0 <= fuel_l <= FUEL_TANK_CAPACITY_L
```

### 2.2. Публичное состояние

Все поля доступны только для чтения.

| Поле | Тип | Значение |
|---|---|---|
| `payload_kg` | `float` | полезная нагрузка, кг |
| `fuel_l` | `float` | остаток топлива, л |
| `current_mode` | `str` | последний полностью достигнутый режим |
| `target_mode` | `str` | запрошенный режим |
| `rotors_deployed` | `bool` | роторы раскрыты |
| `wings_deployed` | `bool` | крылья раскрыты |
| `is_ground` | `bool` | транспорт находится на земле |
| `is_airborne` | `bool` | транспорт находится в воздухе |
| `speed_kmh` | `float` | поступательная скорость |
| `last_transition_path` | `tuple[str, ...]` | режимы последнего завершённого перехода |
| `last_transition_steps` | `tuple[str, ...]` | физические шаги этого перехода |

Начальное состояние:

```text
current_mode == target_mode == "road"
rotors_deployed == False
wings_deployed == False
is_ground == True
is_airborne == False
speed_kmh == 0.0
last_transition_path == ()
last_transition_steps == ()
```

### 2.3. Устойчивые режимы и инварианты

При `current_mode == target_mode` объект обязан точно соответствовать одной строке таблицы.

При `current_mode != target_mode` переход только запрошен, но ещё не начат: положение, скорость, роторы и крылья по-прежнему соответствуют `current_mode`. Промежуточные физические состояния существуют только внутри `transition()`.

| Режим | Земля | Воздух | Скорость | Роторы | Крылья |
|---|---:|---:|---:|---:|---:|
| `road` | `True` | `False` | `0` | `False` | `False` |
| `hover` | `False` | `True` | `0` | `True` | `False` |
| `flight` | `False` | `True` | `>= MIN_FLIGHT_SPEED_KMH` | `False` | `True` |

Общие инварианты:

```text
is_ground == (not is_airborne)
fuel_l >= 0
speed_kmh >= 0
```

Следствия:

- `flight` всегда означает, что транспорт в воздухе, имеет достаточную скорость и держится на крыльях;
- `hover` всегда означает, что транспорт в воздухе, не имеет поступательной скорости и держится на роторах;
- состояние «`current_mode == "flight"`, но фактически зависаем» запрещено;
- промежуточная физическая конфигурация существует только внутри атомарного вызова `transition()` и наружу не наблюдается.

### 2.4. Наблюдаемость переходов

`transition()` атомарен, поэтому промежуточные поля нельзя прочитать во время вызова. Для тестирования после успешного перехода сохраняются:

- `last_transition_path` — последовательность достигнутых устойчивых режимов;
- `last_transition_steps` — последовательность физических шагов.

При ошибке обе записи и всё остальное состояние остаются прежними.

## 3. Переходы состояний

### 3.1. Управление переходом

`change_mode(mode)` только устанавливает `target_mode`. `transition()` выполняет переход `current_mode -> target_mode`.

Если режимы равны, `transition()` ничего не делает и не меняет журнал перехода.

Каждый прямой переход расходует `TRANSITION_FUEL_L == 2.0`. Переход в воздушный режим должен оставить не меньше `MIN_FUEL_L`. Переход на землю может использовать резерв.

### 3.2. Шесть обычных переходов

| Переход | Шаги `last_transition_steps` | Финальная скорость |
|---|---|---:|
| `road -> hover` | `deploy_rotors, vertical_takeoff` | `0` |
| `road -> flight` | `deploy_wings, accelerate_on_ground, takeoff` | `MIN_FLIGHT_SPEED_KMH` |
| `hover -> road` | `vertical_descent, touchdown, retract_rotors` | `0` |
| `hover -> flight` | `deploy_wings, accelerate_with_rotor_support, transfer_lift_to_wings, retract_rotors` | `MIN_FLIGHT_SPEED_KMH` |
| `flight -> hover` | `deploy_rotors, transfer_lift_to_rotors, decelerate_to_zero, retract_wings` | `0` |
| `flight -> road` | `approach_on_wings, touchdown, decelerate_to_zero, retract_wings` | `0` |

Для обычного прямого перехода:

```text
last_transition_path == (source_mode, target_mode)
```

Критический порядок для `flight -> hover`:

1. исходное состояние обязано быть устойчивым `flight`;
2. транспорт находится в воздухе;
3. `speed_kmh >= MIN_FLIGHT_SPEED_KMH`;
4. сначала раскрываются роторы;
5. подъёмная сила передаётся роторам;
6. только затем скорость снижается до нуля и складываются крылья.

Следовательно, переход через `hover` разрешён только в воздухе и при наличии полётной скорости. На земле или при нулевой скорости этот маршрут не применяется.

### 3.3. Аварийная посадка

Обычная воздушная операция не может уменьшить запас ниже `MIN_FUEL_L`. Если `move()` или `hover()` нарушили бы резерв, запрошенная операция отменяется и автоматически выполняется посадка:

| Исходный режим | Условие | Маршрут | Расход |
|---|---|---|---:|
| `hover` | устойчивый `hover` | `hover -> road` | `2.0` |
| `flight` | `is_airborne == True` и `speed_kmh >= MIN_FLIGHT_SPEED_KMH` | `flight -> hover -> road` | `4.0` |

Перед маршрутом `flight -> hover` обязательно проверяются оба условия: транспорт находится в воздухе и имеет полётную скорость. При нарушенном инварианте возникает `InvalidState`; переход через `hover` не запускается.

После автоматической посадки метод завершается без исключения. Для аварии из устойчивого `flight`:

```text
last_transition_path == ("flight", "hover", "road")
last_transition_steps == (
    "deploy_rotors",
    "transfer_lift_to_rotors",
    "decelerate_to_zero",
    "retract_wings",
    "vertical_descent",
    "touchdown",
    "retract_rotors",
)
```

Для аварии из устойчивого `hover` путь и шаги совпадают с обычным `hover -> road`.

Для обычной посадки:

```text
last_transition_path == ("flight", "road")
```

Так тест однозначно различает два маршрута.

## 4. Сценарии

Сценарии используют только публичные методы `LegoVehicle`. Дополнительная обёртка `Pilot` не нужна.

### S-01. Прямой самолётный взлёт и посадка

**Given:** `LegoVehicle(0, 20)` в `road`.

**When:** `change_mode("flight")`, `transition()`.

**Then:** устойчивый `flight`: аппарат в воздухе, скорость не ниже `80`, крылья раскрыты, роторы сложены, путь `("road", "flight")`.

**When:** `change_mode("road")`, `transition()`.

**Then:** устойчивый `road`, путь `("flight", "road")`, остаток `16.0` л.

### S-02. Вертикальный взлёт и переход к полёту

**Given:** `LegoVehicle(0, 30)`.

**When:** выполнить `road -> hover -> flight`.

**Then:** каждый достигнутый режим соответствует таблице 2.3; для `hover -> flight` журнал подтверждает раскрытие крыльев до складывания роторов; остаток `26.0` л.

### S-03. Переход `flight -> hover`

**Given:** устойчивый `flight`.

**When:** запросить `hover` и выполнить `transition()`.

**Then:** исходно аппарат был в воздухе и имел скорость не ниже `MIN_FLIGHT_SPEED_KMH`; итог — устойчивый `hover` со скоростью `0`. Шаги равны строке `flight -> hover` из таблицы 3.2.

### S-04. Аварийная посадка из `hover`

**Given:** `LegoVehicle(0, 9)` переведён в `hover`; осталось `7` л.

**When:** `hover(10, 1.0)` потребовал бы `4` л и нарушил резерв.

**Then:** зависание не выполняется; без исключения выполняется `hover -> road`; остаётся `5` л.

### S-05. Аварийная посадка из `flight`

**Given:** `LegoVehicle(0, 9)` переведён в `flight`; осталось `7` л.

**When:** `move("forward", 11, 1.0)` потребовал бы `3.3` л и нарушил резерв.

**Then:** движение не выполняется; без исключения выполняется `flight -> hover -> road`; `last_transition_path == ("flight", "hover", "road")`; остаётся `3` л.

## 5. Расход топлива

Для `move()` и `hover()`:

```text
load_factor = 1 + 0.5 * payload_kg / MAX_PAYLOAD_KG
fuel_required =
    fuel_rate(current_mode)
    * duration_min
    * power_usage
    * load_factor
```

Где:

| Режим | Расход, л/мин |
|---|---:|
| `road` | `0.10` |
| `hover` | `0.40` |
| `flight` | `0.30` |

Ограничения:

```text
duration_min > 0
0 < power_usage <= 1
```

`move()` моделирует завершённый интервал движения. После него устойчивые `road` и `hover` имеют `speed_kmh == 0`, а устойчивый `flight` сохраняет скорость не ниже `MIN_FLIGHT_SPEED_KMH`.

## 6. Методы и исключения

### 6.1. Иерархия

```text
CrazyVehicleError
└── LegoVehicleError
    ├── InvalidState
    └── NotEnoughFuel
```

Порядок проверок един для всех методов:

1. типы аргументов;
2. значения и диапазоны;
3. текущее состояние;
4. запас топлива.

При любом исключении состояние не изменяется.

### 6.2. `__init__(payload_kg, fuel_l)`

| Условие | Исключение | Сообщение |
|---|---|---|
| аргумент не `float` | `TypeError` | `"параметр <имя_параметра> должен иметь тип float"` |
| `payload_kg` вне диапазона | `ValueError` | `"payload_kg вне допустимого диапазона"` |
| `fuel_l` вне диапазона | `ValueError` | `"fuel_l вне допустимого диапазона"` |

`bool` не считается числом для параметров модели.

### 6.3. `change_mode(target_mode)`

| Условие | Исключение | Сообщение |
|---|---|---|
| `target_mode` не `str` | `TypeError` | `"target_mode должен быть строкой"` |
| неизвестный режим | `ValueError` | `"неизвестный режим: X"` |

Корректный вызов может заменить ранее выбранную цель. Если новая цель равна `current_mode`, запрос перехода отменяется; физическое состояние и топливо не меняются.

### 6.4. `transition()`

| Условие | Исключение | Сообщение |
|---|---|---|
| нарушен инвариант исходного устойчивого режима | `InvalidState` | `"нарушен инвариант режима"` |
| переход в воздух оставил бы меньше `MIN_FUEL_L` | `NotEnoughFuel` | `"недостаточно топлива для сохранения аварийного резерва"` |
| для перехода на землю меньше `TRANSITION_FUEL_L` | `NotEnoughFuel` | `"недостаточно топлива для посадки"` |

Сначала проверяется инвариант исходного режима. После этого при `current_mode == target_mode` метод является no-op.

### 6.5. `move(direction, duration_min, power_usage)`

Допустимые направления:

| Режим | Направления |
|---|---|
| `road` | `forward, backward` |
| `hover` | `up, down, forward, backward, left, right` |
| `flight` | `forward, up, down, left, right` |

| Условие | Исключение | Сообщение |
|---|---|---|
| неверный тип аргумента | `TypeError` | `"параметр <имя_параметра> имеет недопустимый тип"` |
| направление недоступно | `ValueError` | `"направление X недоступно в режиме Y"` |
| `duration_min <= 0` | `ValueError` | `"duration_min должен быть положительным"` |
| `power_usage <= 0` или `> 1` | `ValueError` | `"power_usage должен быть в диапазоне (0, 1]"` |
| `current_mode != target_mode` | `InvalidState` | `"транспорт находится в процессе перехода"` |
| нарушен инвариант режима | `InvalidState` | `"нарушен инвариант режима"` |
| в `road` недостаточно топлива | `NotEnoughFuel` | `"недостаточно топлива"` |

В `hover` и `flight` нарушение резерва не вызывает исключение: движение отменяется и запускается аварийная посадка.

### 6.6. `hover(duration_min, power_usage)`

| Условие | Исключение | Сообщение |
|---|---|---|
| неверный тип аргумента | `TypeError` | `"параметр <имя_параметра> имеет недопустимый тип"` |
| `duration_min <= 0` | `ValueError` | `"duration_min должен быть положительным"` |
| `power_usage <= 0` или `> 1` | `ValueError` | `"power_usage должен быть в диапазоне (0, 1]"` |
| `current_mode != "hover"` или `target_mode != "hover"` | `InvalidState` | `"транспорт не находится в устойчивом режиме hover"` |
| оба режима равны `hover`, но физические поля нарушают таблицу 2.3 | `InvalidState` | `"нарушен инвариант режима"` |

Если зависание нарушило бы резерв, оно отменяется и выполняется `hover -> road` без исключения.

### 6.7. `get_status()`

Не принимает аргументов, не меняет состояние и не генерирует доменных исключений.

Возвращает новый словарь:

```python
{
    "payload_kg": float,
    "fuel_l": float,
    "current_mode": str,
    "target_mode": str,
    "rotors_deployed": bool,
    "wings_deployed": bool,
    "is_ground": bool,
    "is_airborne": bool,
    "speed_kmh": float,
    "last_transition_path": tuple[str, ...],
    "last_transition_steps": tuple[str, ...],
}
```

## 7. Граничные условия

- При `fuel_l == 6.0` переход `road -> flight` разрешён и оставляет ровно `MIN_FUEL_L`.
- При `fuel_l < 6.0` тот же переход вызывает `NotEnoughFuel` без изменения состояния.
- Воздушная операция, оставляющая ровно `MIN_FUEL_L`, разрешена.
- Воздушная операция, оставляющая меньше `MIN_FUEL_L`, отменяется и запускает посадку.
- Значения конструктора на обеих границах допустимы.
- Все сравнения топлива выполняются без скрытого округления; тесты используют `pytest.approx`.

## 8. Вне рамок

Не моделируются координаты, высота, путь, погода, столкновения, повреждения, отказы, вода, хранение данных, сеть, GUI, многопоточность и асинхронные переходы.
